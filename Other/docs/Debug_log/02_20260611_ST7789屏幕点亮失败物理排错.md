## 问题描述

在 SkyStar V2 移植完 ST7789 驱动与背光驱动并编译烧录后，调试控制台串口正常输出日志，背光初始命令执行反馈成功，但**液晶屏幕物理上完全不亮**。

在控制台串口中输入 **backlight 100** 命令，屏幕依然全黑；而在输入 **backlight 0** 时，屏幕背光竟然被物理点亮。自检显示测试命令 **lcd_test** 执行后，屏幕无任何画面响应（维持白屏或花屏或无背光全黑）。

---

## 根因分析

该问题是由三个底层的硬件物理配置错误共同导致的，属于典型的硬件级集成陷阱：

### 1. SPI1 DMA 数据宽度配置错误 (半字配置)
* **成因**：开发规划文档中存在配置误导，将 SPI1 的 TX DMA 数据宽度设为了 **Half Word** (半字，16-bit)。
* **机制**：虽然 ST7789 的像素格式为 16 位 (RGB565)，但 SPI1 外设本身被配置在 8 位的数据发送模式下。当 DMA 被配置为 16 位宽度时，DMA 控制器每次会从内存中读取 16 位宽的数据并写入 SPI 数据寄存器（DR），同时内存指针每次递增 2 个字节。这导致实际发送时只发送了偶数地址的字节，奇数地址的数据全部被跳过丢弃。数据流完全损坏，ST7789 无法接收到正确的初始化指令与参数，液晶屏处于失步状态。

### 2. GPIO 启动初始电平配置错误 (RESET 状态)
* **成因**：CubeMX 默认生成的代码中，片选引脚 **W25Q_CS_Pin**、**LCD_CS_Pin**、复位引脚 **LCD_RST_Pin** 以及数据命令引脚 **LCD_DC_Pin** 的初始化默认输出电平被配成了 **RESET** (低电平)。
* **机制**：低电平对于片选和复位是有效选通信号。上电后，在 `MX_SPI1_Init()` 执行期间，SCK 和 MOSI 引脚会产生因外设配置和引脚复用切换带来的杂散时钟信号。由于片选和复位此时处于低电平选通状态，ST7789 误将这些物理杂散信号识别为了 SPI 帧，导致芯片内部控制器的状态机在运行程序前就彻底紊乱并进入死锁状态，无法响应后续的正常初始化命令。

### 3. TIM10 通道 1 极性配置反转 (HIGH 极性)
* **成因**：CubeMX 配置中将 TIM10 CH1 的 PWM 极性设置为了 **TIM_OCPOLARITY_HIGH**。
* **机制**：天空星核心板的背光驱动电路为低电平点亮。使用高极性配置时，输出的高电平时间对应 CCR 计数值。因此占空比越大，高电平时间越长，屏幕反而越暗；当占空比设置为 100% (亮满) 时，物理引脚输出恒高电平，背光反而彻底熄灭。

## 问题代码

### 1. SPI1 DMA 宽度错误配置 (spi.c)
```c
/* 文件：Core/Src/spi.c，函数：HAL_SPI_MspInit() */
hdma_spi1_tx.Init.PeriphDataAlignment = DMA_PDATAALIGN_HALFWORD; // ❌ 错误：配置为半字
hdma_spi1_tx.Init.MemDataAlignment = DMA_MDATAALIGN_HALFWORD;    // ❌ 错误：配置为半字
```

### 2. GPIO 初始低电平使能错误 (gpio.c)
```c
/* 文件：Core/Src/gpio.c，函数：MX_GPIO_Init() */
HAL_GPIO_WritePin(GPIOE, W25Q_CS_Pin|LCD_CS_Pin|LCD_RST_Pin, GPIO_PIN_RESET); // ❌ 错误：片选和复位拉低导致外部设备被误选通
HAL_GPIO_WritePin(LCD_DC_GPIO_Port, LCD_DC_Pin, GPIO_PIN_RESET);              // ❌ 错误：DC 默认拉低
```

### 3. PWM 极性反转配置 (tim.c)
```c
/* 文件：Core/Src/tim.c，函数：MX_TIM10_Init() */
sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH; // ❌ 错误：高电平有效，与物理电路的低电平点亮特性反转
```

## 可选解决方案

* **方案 A（采用）：修复底层物理配置并优化初始化时序**
  * 将 SPI1 DMA 宽度修正为 **Byte**。
  * 将 GPIO 默认电平修改为 **SET** 高电平，实现上电总线隔离。
  * 将 TIM10 极性修改为 **TIM_OCPOLARITY_LOW**，使亮度控制正向化。
  * 优化 **lcd_init** 时序：清屏刷黑后再使能背光。
  * 优点：直接从根本上解决所有软硬件层冲突，零额外开销。
  * 缺点：无。

---

## 实际修复方式

采用**方案 A**：

### 1. 修改 Core/Src/spi.c
```c
/* 文件：Core/Src/spi.c，函数：HAL_SPI_MspInit() */
hdma_spi1_tx.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE; // ✅ 修复：使用字节对齐
hdma_spi1_tx.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;    // ✅ 修复：使用字节对齐
```

### 2. 修改 Core/Src/gpio.c
```c
/* 文件：Core/Src/gpio.c，函数：MX_GPIO_Init() */
HAL_GPIO_WritePin(GPIOE, W25Q_CS_Pin|LCD_CS_Pin|LCD_RST_Pin, GPIO_PIN_SET); // ✅ 修复：上电时片选与复位强制拉高，隔离总线抖动
HAL_GPIO_WritePin(LCD_DC_GPIO_Port, LCD_DC_Pin, GPIO_PIN_SET);              // ✅ 修复：默认拉高
```

### 3. 修改 Core/Src/tim.c
```c
/* 文件：Core/Src/tim.c，函数：MX_TIM10_Init() */
sConfigOC.OCPolarity = TIM_OCPOLARITY_LOW; // ✅ 修复：配置为低电平有效，匹配硬件电路
```

### 4. 优化初始化清屏时序 (dev_st7789.c)
```c
/* 文件：BSP/Driver/dev_st7789.c，函数：lcd_init() */
void lcd_init(void)
{
    port_spi_init(ST7789_SPI_BUS);
    st7789_hw_reset();
    st7789_write_cmd(ST7789_CMD_SLEEP_OUT);
    port_tick_delay_ms(120);
    lcd_set_rotation(0);
    st7789_reg_init();

    // ✅ 修复：在背光点亮前先物理清屏为纯黑色，规避白屏/花屏瞬闪
    lcd_fill_color(0, 0, lcd_get_width(), lcd_get_height(), LCD_COLOR_BLACK);

    bsp_backlight_init();
}
```

## 举一反三

**防坑原则**：

1. **总线设备隔离原则**：所有通过低电平选通的 SPI/I2C 外设（如 CS、RST 等），其 GPIO 控制引脚在 `MX_GPIO_Init()` 初始配置时**必须默认输出高电平**。严禁将片选引脚初始化为低电平，否则在上电和复位初始化期间，时钟线的任何毛刺都会被设备当作总线命令，导致芯片内部状态机锁死。
2. **DMA 宽度匹配原则**：当总线位宽为 8 位时，DMA 发送和接收的对齐格式必须配置为 **Byte**，千万不能被“一次传输 16 位像素”等应用层概念混淆。
3. **极性检查清单**：凡是涉及 PWM 驱动（背光、LED 等）或外部中断（EXTI），必须先查阅硬件原理图确认触发的物理电平极性（高电平有效或低电平有效），在 CubeMX 配置中显式予以对应。
