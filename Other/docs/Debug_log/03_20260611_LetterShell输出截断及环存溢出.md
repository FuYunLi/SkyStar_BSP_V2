## 问题描述

在 SkyStar V2 串口控制台输入 **help** 命令尝试列出所有系统已导出的命令时，控制台终端输出不全，命令列表在中间某一行被莫名截断。多轮输入后，截断发生的行号及字符位置不完全固定，且终端没有任何错误日志输出，系统仍在正常轮询。

---

## 根因分析

该问题是由上层字符写需求与底层异步非阻塞缓冲区之间的容量错配、速率错配以及接口返回语义未被处理共同导致的：

### 1. 缓冲区大小与物理发送速率错配
* **机制**：板级串口驱动在 **bsp_uart.c** 中为串口发送逻辑分配了大小为 **2KB** 的环形发送缓冲区。物理串口波特率为 115200，折算数据传输速率仅约 11.5 KB/s。
* **现象**：当调用 Letter Shell 的 **help** 命令时，程序会在极短的时间内（微秒级）循环输出上千字节的命令及其描述说明。此时数据量迅速填满发送环形缓冲区。

### 2. 接口返回语义被忽略导致丢弃
* **机制**：底层接口 **bsp_uart_write** 的底层实现是异步写缓冲区。如果缓冲区的空闲空间不足以容纳本次写入的长度，底层驱动将直接返回失败码 **BSP_ERROR**。
* **后果**：在 **bsp_shell.c** 的移植接口中，原先的 **user_shell_write** 函数在调用 **bsp_uart_write** 失败后，直接将失败转化为返回值 0 向上返回。由于 Letter Shell 作为上层应用只负责将命令输出一次，当底层接口返回 0 时，它并不会执行任何重试、分包或阻塞等待，直接认为后续数据无法写入并直接丢弃。导致物理上输出的命令列表被无声截断。

## 问题代码

### 移植层未处理缓冲区满状态 (bsp_shell.c)
```c
/* 文件：BSP/Board/bsp_shell.c，函数：user_shell_write() */
static short user_shell_write(char *data, unsigned short len)
{
    if (bsp_uart_write((const uint8_t *)data, len) == BSP_OK)
    {
        return len;
    }
    return 0; // ❌ 错误：在环形缓冲区满写入失败时，直接丢弃剩余字符并返回 0
}
```

## 可选解决方案

* **方案 A：增大发送环形缓冲区的容量**
  * 优点：开发实现极简，只需要修改宏定义。
  * 缺点：只能缓解，不能根除问题。如果命令数进一步增加，或系统有其他后台任务打印大量日志，依旧会发生溢出截断；同时会白白浪费有限的内部 SRAM 资源。
* **方案 B（采用）：分包循环写入 + 中断腾空等待 + 超时防死锁**
  * 优点：在写数据时动态查询缓冲区的空闲空间，分包流式写入。若无空间则短暂等待，由于串口发送是由 DMA 中断在后台异步消耗的，中断会不断腾出空间，从而使数据能安全且完整地输出。同时限制 500 毫秒的最长等待时间，确保串口硬件异常时系统不挂死。
  * 缺点：在串口输出大量数据时，会将主循环短暂阻塞（在此硬件及场景下影响可以忽略不计）。

## 实际修复方式

采用**方案 B**：

### 修改 BSP/Board/bsp_shell.c

```c
/* 文件：BSP/Board/bsp_shell.c，函数：user_shell_write() */
static short user_shell_write(char *data, unsigned short len)
{
    unsigned short remaining = len;
    uint32_t start_tick = HAL_GetTick();

    while (remaining > 0)
    {
        uint16_t free_space = bsp_uart_get_tx_free_space();
        if (free_space > 0)
        {
            uint16_t write_len = (remaining < (unsigned short)free_space) ? remaining : (unsigned short)free_space;
            if (bsp_uart_write((const uint8_t *)data, write_len) == BSP_OK)
            {
                data += write_len;
                remaining -= write_len;
                start_tick = HAL_GetTick(); // 重置超时计时器
            }
        }
        else
        {
            // 超过 500 毫秒未释放空间则强制退出，防止硬件挂死导致死锁
            if (HAL_GetTick() - start_tick > 500U)
            {
                break;
            }
        }
    }

    return len - remaining;
}
```

## 举一反三

**防坑原则**：

1. **环存流式写入保障**：在将无流控的普通字符流（如 Shell 打印、elog 打印）对接到具有固定大小环形缓冲区的异步驱动时，写入包装层**必须具备分包连续写入能力**。除非上层框架本身支持状态重试，否则不能将部分写入或写入失败直接丢给上层，必须在驱动层做重试与腾空等待。
2. **防挂死防御性设计**：所有的纯软件等待循环（`while` 轮询某寄存器或缓冲状态）**必须设计基于时间的物理超时退出逻辑**。尤其是在依赖硬件中断来改变状态标志的循环中，必须防止因硬件损坏、时钟未开启或中断未使能导致的永久性系统死锁。
