# 污染处理流程

## 概述

当Agent错误提交或推送导致仓库污染时，按照本文档流程进行恢复。

***

## 污染类型分类

| 污染类型 | 严重程度 | 恢复难度 | 恢复时间 |
|---------|---------|---------|---------|
| **本地提交错误** | 低 | 低 | 1分钟 |
| **本地分支污染** | 中 | 中 | 5分钟 |
| **远程分支污染** | 高 | 高 | 10分钟 |
| **远程master污染** | 极高 | 高 | 15分钟 |

***

## 污染检测

### 自动检测脚本

```bash
#!/bin/bash
# scripts/check-pollution.sh

echo "=== 仓库污染检测 ==="

# 检查1: 本地与远程分叉
diverged=$(git status | grep "have diverged" | wc -l)
if [ "$diverged" -gt 0 ]; then
  echo "⚠️ 警告: 本地与远程已分叉"
  git status
fi

# 检查2: 关键文件是否存在
critical_files=(
  "BSP/Interface/port_uart.h"
  "BSP/Board/bsp_board.h"
  "Docs/代码规范.md"
)

for file in "${critical_files[@]}"; do
  if [ ! -f "$file" ]; then
    echo "❌ 错误: 关键文件缺失: $file"
  else
    echo "✅ 关键文件存在: $file"
  fi
done

# 检查3: 最近提交的文件变更
echo ""
echo "=== 最近5次提交的文件变更 ==="
git log --oneline -5 | while read hash msg; do
  echo "提交: $hash $msg"
  git show --stat $hash | head -20
  echo ""
done

# 检查4: 检查是否有大量删除
echo ""
echo "=== 检查大规模删除 ==="
git diff --numstat HEAD~5..HEAD | awk '{if($2>100) print "⚠️ 大规模删除: "$3" (删除"$2"行)"}'
```

## 恢复方案

### 方案A: 强制回退（推荐，适合未公开项目）

**适用场景**：
- 项目未公开，历史记录不重要
- 需要快速恢复
- 远程仓库有强制推送权限

**步骤**：

```bash
#!/bin/bash
# 方案A: 强制回退

echo "=== 方案A: 强制回退 ==="

# 步骤1: 备份当前工作
git stash push -m "污染恢复前备份-$(date +%Y%m%d-%H%M%S)"
git branch backup-污染前-$(date +%Y%m%d-%H%M%S)

# 步骤2: 找到污染前的最后一个正确提交
echo "最近提交历史："
git log --oneline -10
echo ""
read -p "请输入污染前的正确提交哈希: " correct_commit

# 步骤3: 重置到正确提交
git reset --hard "$correct_commit"

# 步骤4: 确认强制推送
echo ""
echo "⚠️ 警告: 即将强制推送到远程，这将覆盖远程历史！"
read -p "确认强制推送？: " confirm

if [ "$confirm" = "y" ]; then
  git push origin master --force
  echo "✅ 远程仓库已恢复"
else
  echo "❌ 取消操作"
  exit 1
fi

# 步骤5: 恢复工作
git stash pop

# 步骤6: 验证
echo ""
echo "=== 验证恢复结果 ==="
git log --oneline -5
echo ""
echo "✅ 恢复完成"
```

**优点**：
- 干净彻底，历史简洁
- 恢复速度快

**缺点**：
- 会丢失污染提交的历史
- 需要强制推送权限

***

### 方案B: 新分支隔离（适合已公开项目）

**适用场景**：
- 项目已公开，不能改变历史
- 需要保留完整历史
- 不想强制推送

**步骤**：

```bash
#!/bin/bash
# 方案B: 新分支隔离

echo "=== 方案B: 新分支隔离 ==="

# 步骤1: 找到污染前的正确提交
echo "最近提交历史："
git log --oneline -10
echo ""
read -p "请输入污染前的正确提交哈希: " correct_commit

# 步骤2: 从正确提交创建新分支
git checkout -b master-clean "$correct_commit"

# 步骤3: 推送新分支
git push origin master-clean

# 步骤4: 在远程仓库设置master-clean为新的默认分支
echo ""
echo "⚠️ 请在远程仓库（Gitee/GitLab）执行以下操作："
echo "1. 设置 master-clean 为新的默认分支"
echo "2. 删除污染的 master 分支"
echo "3. 重命名 master-clean 为 master"

# 步骤5: 本地更新
echo ""
read -p "远程操作完成后，按回车继续..."
git fetch origin
git checkout master
git branch -D master-clean

echo "✅ 恢复完成"
```

**优点**：
- 不改变历史，最安全
- 可以保留污染分支作为参考

**缺点**：
- 需要在远程平台操作
- 步骤较多

***

### 方案C: Revert污染提交（最安全）

**适用场景**：
- 项目已公开，必须保留历史
- 需要明确记录污染和恢复过程
- 团队协作项目

**步骤**：

```bash
#!/bin/bash
# 方案C: Revert污染提交

echo "=== 方案C: Revert污染提交 ==="

# 步骤1: 查看污染提交
echo "污染提交列表："
git log --oneline -10
echo ""
echo "请按从新到旧的顺序输入污染提交哈希（用空格分隔）："
read -a pollution_commits

# 步骤2: 切换到远程master
git fetch origin
git checkout origin/master

# 步骤3: 逐个revert污染提交（从最新到最旧）
for commit in "${pollution_commits[@]}"; do
  echo "Revert 提交: $commit"
  git revert "$commit" --no-edit
  
  if [ $? -ne 0 ]; then
    echo "❌ Revert失败: $commit"
    echo "请手动解决冲突后继续"
    read -p "解决冲突后按回车继续..."
    git revert --continue
  fi
done

# 步骤4: 推送revert提交
echo ""
read -p "确认推送revert提交？: " confirm

if [ "$confirm" = "y" ]; then
  git push origin master
  echo "✅ 远程仓库已恢复"
else
  echo "❌ 取消操作"
  exit 1
fi

# 步骤5: 合并到本地
git checkout master
git merge origin/master

echo "✅ 恢复完成"
```

**优点**：
- 不改变历史，最安全
- 明确记录污染和恢复过程
- 团队成员可以看到发生了什么

**缺点**：
- 历史记录会有污染提交+revert提交
- 如果污染提交很多，历史会比较乱

## 污染预防措施

### Git Hooks

```bash
# .git/hooks/pre-push
# 防止Agent意外推送

while read local_ref local_sha remote_ref remote_sha
do
  branch=$(echo $remote_ref | sed 's|refs/heads/||')
  
  # 检查是否推送到受保护分支
  if [ "$branch" = "master" ] || [ "$branch" = "develop" ]; then
    echo "❌ 错误: 禁止直接推送到 $branch 分支"
    echo "请通过Pull Request方式合并"
    exit 1
  fi
  
  # 检查是否是Agent环境
  if [ "$TRAE_AGENT" = "true" ]; then
    echo "❌ 错误: Agent禁止执行push操作"
    exit 1
  fi
done

exit 0
```

### CI/CD 检查

```yaml
# .github/workflows/code-protection.yml
name: 代码保护检查

on:
  push:
    branches: [master, develop]
  pull_request:
    branches: [master, develop]

jobs:
  check-deletion:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
        with:
          fetch-depth: 0
      
      - name: 检查关键文件删除
        run: |
          deleted_files=$(git diff --name-only --diff-filter=D origin/develop...HEAD)
          
          critical_files=(
            "BSP/Interface/port_uart.h"
            "BSP/Board/bsp_board.h"
          )
          
          for file in "${critical_files[@]}"; do
            if echo "$deleted_files" | grep -q "$file"; then
              echo "❌ 错误: 检测到关键文件删除: $file"
              exit 1
            fi
          done
```

## 紧急联系清单

### 污染发生时

1. **立即冻结Agent权限**
2. **记录污染详情**（提交哈希、删除文件、影响范围）
3. **选择恢复方案**（根据项目情况选择A/B/C）
4. **执行恢复**（按步骤执行）
5. **验证恢复结果**（编译、测试）
6. **总结教训**（更新权限控制规范）

### 需要人工确认的操作

- 强制推送到master
- 删除关键文件
- 大规模代码修改（>100行）
- 修改配置文件
- 修改分支保护规则
