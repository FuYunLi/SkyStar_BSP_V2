# 分支管理规范

## 分支策略

```
master (受保护)
  │
  ├── develop (集成分支)
  │     │
  │     ├── feature/M1-uart-interface
  │     ├── feature/M2-letter-shell
  │     ├── feature/M3-easy-logger
  │     └── ...
  │
  ├── release/v0.1 (阶段零发布)
  ├── release/v0.2 (阶段一发布)
  └── ...
  │
  └── hotfix/紧急修复分支
```

***

## 分支命名规范

| 分支类型 | 命名格式 | 示例 | 权限 |
|---------|---------|------|------|
| **功能分支** | `feature/M{编号}-{简述}` | `feature/M1-uart-interface` | Agent可创建,不可推送 |
| **修复分支** | `fix/{问题简述}` | `fix/port-uart-dma-race` | Agent可创建,不可推送 |
| **发布分支** | `release/v{阶段号}` | `release/v0.1` | 仅人工创建推送 |
| **热修分支** | `hotfix/{版本号}-{简述}` | `hotfix/v0.1-critical-bug` | 仅人工创建推送 |
| **备份分支** | `backup/{描述}-{日期}` | `backup/30号参考-20250531` | 仅人工创建推送 |

***

## 分支保护规则

### master 分支（最高保护级别）

```yaml
protected: true
require_pull_request: true
required_approving_review_count: 1  # 需要人工审批
allow_force_pushes: false
allow_deletions: false
status_checks:
  - 编译检查
  - 代码规范检查
```

### develop 分支（中等保护级别）

```yaml
protected: true
require_pull_request: true
required_approving_review_count: 0  # Agent可合并到develop
allow_force_pushes: false
allow_deletions: false
```

### feature 分支（低保护级别）

```yaml
protected: false  # 不保护，可以自由操作
allow_force_pushes: true  # 允许强制推送（仅限自己的分支）
allow_deletions: true  # 允许删除
```

## 工作流程

### 功能开发流程

```
1. 人工创建功能分支
   git checkout develop
   git checkout -b feature/M1-uart-interface

2. Agent在功能分支开发
   - 读取当前阶段文档
   - 实施开发（本地修改）
   - 本地提交（git commit，禁止push）

3. Agent完成开发
   - 输出PR描述
   - 等待人工审查

4. 人工审查
   - 检查代码质量
   - 运行测试验收
   - 确认无污染

5. 人工合并
   git checkout develop
   git merge feature/M1-uart-interface
   git push origin develop

6. 清理分支
   git branch -d feature/M1-uart-interface
```

### 发布流程

```
1. 阶段完成后，人工创建发布分支
   git checkout develop
   git checkout -b release/v0.1

2. 发布验收
   - 运行完整测试
   - 检查所有功能
   - 确认无问题

3. 合并到master
   git checkout master
   git merge release/v0.1
   git tag v0.1
   git push origin master --tags

4. 清理分支
   git branch -d release/v0.1
```

### 紧急修复流程

```
1. 从master创建热修分支
   git checkout master
   git checkout -b hotfix/v0.1-critical-bug

2. 修复问题
   - 定位问题
   - 修复代码
   - 本地测试

3. 合并到master和develop
   git checkout master
   git merge hotfix/v0.1-critical-bug
   git tag v0.1.1
   git push origin master --tags
   
   git checkout develop
   git merge hotfix/v0.1-critical-bug
   git push origin develop

4. 清理分支
   git branch -d hotfix/v0.1-critical-bug
```

## 禁止操作清单

### 绝对禁止（无论任何情况）

```bash
# 禁止直接推送到master
git push origin master

# 禁止直接推送到develop（Agent）
git push origin develop

# 禁止强制推送到受保护分支
git push --force origin master
git push --force origin develop

# 禁止删除受保护分支
git push origin --delete master
git push origin --delete develop
```

### 需要审批（Agent操作）

```bash
# 所有提交需人工审查
git commit

# 推送功能分支需确认
git push origin feature/*

# 删除文件需确认
rm file.txt

# 大规模修改（>10文件）需审批
```

## 分支状态检查

### 检查脚本

```bash
#!/bin/bash
# scripts/check-branch.sh

# 检查当前分支
current_branch=$(git rev-parse --abbrev-ref HEAD)

# 检查是否在受保护分支
if [ "$current_branch" = "master" ] || [ "$current_branch" = "develop" ]; then
  echo "❌ 错误: 当前在受保护分支 $current_branch"
  echo "请切换到功能分支进行开发"
  exit 1
fi

# 检查是否有未提交的修改
if ! git diff-index --quiet HEAD --; then
  echo "⚠️ 警告: 有未提交的修改"
  git status
fi

echo "✅ 分支检查通过: $current_branch"
```

## Git Hooks 配置

### pre-push hook（防止误推送）

```bash
#!/bin/bash
# .git/hooks/pre-push

while read local_ref local_sha remote_ref remote_sha
do
  branch=$(echo $remote_ref | sed 's|refs/heads/||')
  
  # 检查是否推送到受保护分支
  if [ "$branch" = "master" ] || [ "$branch" = "develop" ]; then
    echo "❌ 错误: 禁止直接推送到 $branch 分支"
    echo "请通过Pull Request方式合并"
    echo ""
    echo "如果你是人工操作，请临时禁用此hook:"
    echo "  git push --no-verify origin $branch"
    exit 1
  fi
  
  # 检查是否是Agent环境
  if [ "$TRAE_AGENT" = "true" ]; then
    echo "❌ 错误: Agent禁止执行push操作"
    echo "请创建Pull Request等待人工审查"
    exit 1
  fi
done

exit 0
```

### pre-commit hook（代码规范检查）

```bash
#!/bin/bash
# .git/hooks/pre-commit

# 检查代码格式
if command -v clang-format &> /dev/null; then
  changed_files=$(git diff --cached --name-only --diff-filter=ACM | grep -E '\.(c|h|cpp|hpp)$')
  
  if [ -n "$changed_files" ]; then
    echo "检查代码格式..."
    for file in $changed_files; do
      if ! clang-format --dry-run --Werror "$file"; then
        echo "❌ 错误: $file 格式不符合规范"
        echo "请运行: clang-format -i $file"
        exit 1
      fi
    done
  fi
fi

echo "✅ 代码规范检查通过"
exit 0
```
