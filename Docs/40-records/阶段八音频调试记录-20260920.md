# 阶段八音频调试记录(M30-M32)

> 日期:2026-09-20
> 分支:feature/M32-wav-player(基点 zcode_bsp)
> 结论:M30/M31/M32 全部验收通过;遗留 Ymodem 写入损坏与 FatFS LFN 两个问题,已登记

---

## 1. 最终成果

- M30:`port_i2s` + `bsp_bus` 总线仲裁,`audio_bus_switch` 双向切换验证通过
- M31:`dev_es8388`(RT-Thread 官方序列)+ `dev_ht6872`,`audio_init/set_vol/pa` 验收通过
- M32:`bsp_audio` 双缓冲播放引擎,读卡器导入的 `251213.wav`(44100Hz/2ch/16bit)喇叭正常播放

## 2. 调试过程与根因(按时间序)

### 2.1 仲裁器切换后无法切回(BSP_BUSY)

现象:`audio_bus_switch i2s` 成功后 `audio_bus_switch spi` 返回 -5。
根因:I2S2 侧占用权无人释放,手动切换是"接管"语义。
修复:demo 命令先 release 当前 owner 再 acquire。

### 2.2 IMU 初始化失败(ret=-1)——开关浮空

现象:开机 `imu_read` 报 BSP_ERROR。
根因:PCA9555 Port0 Pin2(模拟开关控制)在旧 bsp_imu_init 中被显式配为输出拉低;
上收到仲裁器后,仲裁器认为"默认已是 SPI2 侧"跳过配置,Pin2 保持复位高阻态,
控制网络无外部上下拉(原理图已警告),总线随机选通。
修复:bsp_bus_acquire 首次调用时懒初始化,显式驱动 Pin2 到当前物理侧电平。

### 2.3 flash_id 在音频侧卡死系统(未修,已登记)

根因:dev_w25q 全链路 BSP_WAIT_FOREVER + 忽略 port_spi 返回值;总线被 I2S2 仲裁走后
HAL 轮询永不满足,Shell 线程永久阻塞。已登记 ARCHITECTURE.md 第 9 节,
计划 M32 收尾或后续把 W25Q 路径接入 bsp_bus 一并收口。

### 2.4 ES8388 I2C 无应答(ret=-7)

根因:port_i2c 约定传 8-bit 从机地址(7-bit 左移一位),ES8388 手册的 0x10 是 7-bit。
修复:ES8388_DEV_ADDR = 0x10U << 1(=0x20)。PCA9555 的 0x40 即此约定。

### 2.5 SD 卡识别失败(HAL ErrorCode 0x04000004)——最大时间黑洞

现象:fatfs_test mount 报 SDIO 物理初始化失败;重插卡、换上拉、ClockDiv 0/8、
PLLQ 7/8 全部组合无效。出厂固件(RT-Thread,读卡正常)对照一度误导方向。

诊断手段:强定义 BSP_SD_Init(覆盖 FATFS Target 弱符号)逐命令打日志,
发现 CMD8/ACMD41 响应寄存器全 0(卡应答内容坏)。

**根因(对照实验锁定)**:7 月 17 日 hotfix e75e6c3 重写 port_sdio 时删掉了
`MX_SDIO_SD_Init()` 调用(重填 hsd 句柄)与 BusWide 强制 1-bit 两行,引入回归;
M29 只用 SPI Flash 未复测 TF 卡,缺陷潜伏两个多月。
烧录 hotfix 之前的 1bfcfef(M28 时代)固件 SD 正常 → 石锤。

修复:port_sdio_init 恢复 MX_SDIO_SD_Init() + BusWide=1B(加"勿删"注释),
保留 hotfix 的热拔插守卫。PLLQ=8/ClockDiv=8/NOPULL 维持 M28 原值未动。

教训:①对照实验必须控制变量(本例中"出厂固件正常"与"我们固件失败"之间
差异远不止一处,差点误导到时钟树);②修改初始化流程的 hotfix 必须回归测试
所有受影响外设,不能只测改动点。

### 2.6 Ymodem 传输 Code 5(文件打开失败)→ LFN

根因:FatFS ffconf.h `_USE_LFN=0` 不支持长文件名,Tour_France.wav(15 字符)
建文件被拒;skystar.txt(8.3)正常。临时方案:改用 8.3 文件名 tour.wav 传输成功。

### 2.7 Ymodem 写入损坏(未修,已登记)

现象:传输 100% 成功、CRC 全对,但读回文件头第 9-12 字节为垃圾
(本地 RIFF...WAVE,卡内 RIFF+长度正确+`B2 BB BB BB`)。
前 8 字节完好、第 9 字节起坏;排除播放侧(读卡器文件播放正常)。
嫌疑:Ymodem 首个 1024 字节包写入时与 FatFS 缓冲交互的缺陷,
或 bsp_uart RX 环形缓冲在高速连续流下的字节丢失(与 ARCHITECTURE 第 9 节
port_uart "两次 IDLE 间连流超过 DMA 缓冲静默覆写"已知问题吻合)。
待查方向:sd_read 对比卡内 tour.wav 与源文件的损坏分布(仅头部 or 随机),
若随机丢字节则坐实 port_uart RX 溢出。

## 3. 遗留问题清单

| 问题 | 严重度 | 计划 |
|---|---|---|
| Ymodem 写入损坏(2.7) | 高(阻塞串口传文件) | 结合 port_uart RX 已知缺陷排查 |
| FatFS LFN 关闭(2.6) | 中(歌名超 8.3 无法建) | ffconf.h 开 _USE_LFN=1(静态缓冲) |
| dev_w25q 无限等待卡死(2.3) | 中 | 接入 bsp_bus 或有限超时 |
| port_uart RX 连流覆写(既有) | 中 | ARCHITECTURE 第 9 节已有方向 |

## 4. 环境备注

- 调试中临时改过的 PLLQ=7/上拉/ClockDiv=0 均已回退,当前=M28 实测正常值
- **待清遗留(已随批次合入,记录在此)**:`SkyStar_BSP_HAL.ioc` 里 SDIO 引脚(PC8-PC12/PD2)仍带 `GPIO_PuPd=GPIO_PULL_UP`,而 `Core/Src/sdio.c` 生成码是 `GPIO_NOPULL`——固件实测正常值是无上拉的,两者不一致。下次 CubeMX 重新生成会把内部上拉静默写入固件,需先决定:回退 .ioc 这 6 行(与现固件一致)或保留并重新生成且复测读卡
- ymodem_sender.py 的 ACK 等待窗口临时放宽到 40s(未回退,无害)
- 串口工具占用 COM3 会致脚本 PermissionError,需先关终端
