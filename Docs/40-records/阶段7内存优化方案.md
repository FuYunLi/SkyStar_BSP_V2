# 阶段七内存优化方案

为了确保系统在后续引入以太网协议栈（LwIP）、SDIO文件系统（FatFS）以及音频解码等内存消耗大户时不会出现 Flash 溢出或 RAM 枯竭，本方案针对当前 BSP 的完成状态制定了专项优化路径。

---

## 一、 当前资源现状与瓶颈分析

根据 **SkyStar_BSP_HAL.map** 映射文件的量化审计，系统当前面临如下物理瓶颈：
*   **Flash 瓶颈**：当前占用约 **397 KB**（占比 **77.6%**），剩余可用空间仅约 **115 KB**。
*   **RAM 瓶颈**：SRAM 共占用约 **97 KB**（占比 **76.0%**），剩余可用空间约 **30.5 KB**。
*   **隐形闲置资源**：STM32F407 芯片内部高达 **64 KB** 的 **CCM RAM** 目前未进行任何配置，处于完全闲置状态。
*   **RAM 消耗大户**：**app_lcd_demo.o** 的静态显存缓冲区占用了 **28.1 KB**；LVGL 的内建堆空间 **lv_mem_core_builtin.o** 占用了 **32.0 KB**。二者合计消耗了 **60.1 KB**。

---

## 二、 RAM 空间优化分类与具体操作

针对 RAM 的优化原则是：**激活 CCM RAM，释放通用 SRAM，预留物理 DMA 通道。**

### 1. 激活 64 KB CCM RAM（物理地址 0x10000000）
*   **核心原理**：CCM RAM 直接挂载在 D-Bus 总线上，读写速度极快，适合存放堆栈和变量。但它不经过 AXI 总线矩阵，因此 **DMA 无法访问 CCM RAM**（若通过 DMA 读写此区域将直接触发 **HardFault**）。因此，必须将**非 DMA 访问**的静态大数组和任务栈强制定位至此。
*   **具体操作**：
    1. 打开 Keil 的分散加载文件 **SkyStar_BSP_HAL.sct**。
    2. 在其中手动添加独立的执行域 **RW_IRAM_CCM**。修改后的分散加载文件示例如下：

```link
LR_IROM1 0x08000000 0x00080000  {    ; 512KB Flash 区域
  ER_IROM1 0x08000000 0x00080000  {
   *.o (RESET, +First)
   *(InRoot$$Sections)
   .ANY (+RO)
   .ANY (+XO)
  }
  RW_IRAM1 0x20000000 0x00020000  {  ; 128KB SRAM1 + SRAM2 物理连续区域
   .ANY (+RW +ZI)
  }
  RW_IRAM_CCM 0x10000000 0x00010000  { ; 64KB CCM RAM 独立区域
   lv_mem_core_builtin.o (+RW +ZI)    ; 强制将 LVGL 静态堆移入 CCM RAM
   *(.ccmram)                          ; 强制将所有修饰了 .ccmram 属性的变量移入此区
  }
}
```

    3. 在 Keil 的 **Project -> Options for Target -> Linker** 选项卡中，取消勾选 **Use Memory Layout from Target Dialog**，并引入此修改后的 **sct** 文件。
    4. 在代码中，对于所有不需要 DMA 参与的非局部变量、大数组，使用 **__attribute__((section(".ccmram")))** 修饰符进行定义。例如：

```c
__attribute__((section(".ccmram"))) uint8_t g_system_temp_buf[2048];
```

### 2. 剪裁 LVGL 内部动态堆（LV_MEM_SIZE）
*   **具体操作**：
    1. 打开 **lv_conf.h** 文件。
    2. 将 **LV_MEM_SIZE** 宏的定义由当前默认的 **(32 * 1024U)**（即 32KB）修改为 **(24 * 1024U)**（即 24KB）或更低。对于以仪表盘和时钟为主的嵌入式界面，24KB 的内部堆空间完全能够满足组件的动态渲染申请。

### 3. 双缓冲与物理画板显存微调
*   **具体操作**：
    1. 在接口文件 **lv_port_disp.c** 中，严禁分配过大的屏幕显存。目前配置为全屏或半屏会导致严重的 SRAM 浪费。
    2. 采用**小显存双缓冲 + DMA 刷屏**模式。将画板缓冲区大小限制在屏幕高宽的十分之一。例如，对于 320x240 的屏幕，定义大小为 **320 * 10 * 2** 字节（共 6.4 KB），定义两个这样的数组，总计只占用 **12.8 KB** 的物理 SRAM。

## 三、 Flash 空间优化分类与具体操作

针对 Flash 的优化原则是：**函数级死码消除，精简 GUI 组件与字库，大资产外置化。**

### 1. 开启编译器/链接器死码消除（DCE）
*   **具体操作**：
    1. 打开 Keil 的 **Project -> Options for Target -> C/C++** 面板。
    2. 勾选 **One ELF Section per Function** 选项。该选项会让编译器将每一个函数作为独立的节（Section）编译。
    3. 打开 **Linker** 面板，确保勾选了 **Unused Section Elimination**（丢弃未引用节）。如此一来，链接器会自动过滤并删除所有未在代码中显式调用的底层驱动函数，而不需要做整包静态链接。
    4. 将优化级别（**Optimization**）调整为 **-Os** (Optimize for Size)，以体积最小化为主要编译输出目标。

### 2. 精简 LVGL 小部件与字库
*   **具体操作**：
    1. 打开 **lv_conf.h**，找到小部件使能部分。
    2. 将当前未使用的复杂小部件全部修改为 **0**（禁用）。建议禁用的模块包括：**LV_USE_CALENDAR**、**LV_USE_KEYBOARD**、**LV_USE_CHART**、**LV_USE_TABLE**、**LV_USE_MENU**、**LV_USE_MSGBOX**、**LV_USE_SPINBOX**。
    3. 找到默认主题配置，将 **LV_USE_THEME_DEFAULT** 修改为 **0**。这可以防止默认主题因静态引用将大量多余小部件强制打包到固件中。
    4. 找到字库配置，将 **LV_FONT_MONTSERRAT_14** 设为 **0**，彻底停用内建的 14 号西文字库（可节省约 13KB 的 RO Data 空间）。

### 3. 应用层测试 Demo 的阶段性剥离
*   **具体操作**：
    1. 当前工程中包含大量的 **app_xxx_demo.c** 文件（如 **app_shell_demo.c**、**app_spi_demo.c** 等）。它们定义了大量的调试命令及对应的静态提示字符串，极耗 Flash 空间。
    2. 在项目逻辑统合阶段，应在 Keil 工程的物理目录树中，右键选中这些 **app_xxx_demo.c**，在属性中取消勾选 **Include in Build**。
    3. 仅保留统一的系统核心入口 **app_main.c** 和系统监控 **app_sys_monitor.c**，将所需的周期任务统合为任务链。

### 4. 图片与大型资产外置化
*   **具体操作**：
    1. 严禁使用图片取模工具生成大数组直接写进 `.c` 文件编译。
    2. 阶段七在完成 **Ymodem** 驱动移植后，将图片资产（**.png**、**.bin**）及全量汉字字库文件，直接通过串口以 **Ymodem** 协议写入板载 W25Q128 Flash 中的 LittleFS 文件系统。
    3. 在代码中通过 **lv_fs** 模块动态读取文件，这样可以保证片内 Flash 始终维持在 **300 KB** 以下的安全水平。

## 四、 优化效果预测与实施时间表

| 优化项目 | 预计释放 Flash | 预计释放 SRAM | 备注 |
| :--- | :--- | :--- | :--- |
| **激活 CCM RAM** | 0 KB | **32 KB** | LVGL 动态堆搬移，释放主 SRAM 空间给 DMA 使用 |
| **LVGL 组件与字库剪裁** | **45 KB** | 8 KB | 减少小部件代码段与 RO 字库，收缩 LVGL 动态堆 |
| **Demo 剥离与编译器调优** | **25 KB** | 33 KB | 排除冗余测试 Demo 与静态缓冲（包含 LCD 测试缓存） |
| **资产外置化 (LittleFS)** | **无限** | 0 KB | 避免图片取模占用片内 ROM |
| **合计预测** | **约 70 KB** | **约 73 KB** | **优化后片内 Flash 占用回落至 320KB 左右，主 SRAM 仅用 25KB，腾出大量资源承载 LwIP 和音频** |
