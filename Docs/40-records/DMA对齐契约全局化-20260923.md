## 1. 设计：三级防线与真实落点

方案文档原写"L1 落在 `port_sdio`"。**核实后不成立**：`port_sdio` 只有 init/在位/容量/错误码四类接口，
SD 块读写实际走 `FATFS/Target/sd_diskio.c` → `bsp_driver_sd.c` 的 `BSP_SD_*Blocks_DMA`（CubeMX 弱符号胶水），
用户指针在那里才变成硬件地址。为不把 FatFs 类型上抬进 Interface 层（依赖方向铁律），守卫落在 disk 层。

| 层 | 落点 | 行为 |
|---|---|---|
| L1 | `FATFS/Target/sd_diskio.c` `SD_read/SD_write` 入口 | 缓冲非 4 字节对齐、或不在 DMA 可达区（CCM 0x10000000 不可达）→ `RES_PARERR`，**只拒绝不中转**，专拦绕过 VFS 直接操作 FatFs 的调用；附 `SD_GetBufRejectCount()` 供自检区分"被拒"与"写坏" |
| L2 | `BSP/Board/bsp_file.c` | 全部文件读写的唯一入口，不合规请求自动**段首/段尾走 FatFS 窗口、段体批量整扇区经 1KB 对齐暂存区**中转；附 `bsp_file_get_align_stage_count()` 证明中转确实发生 |
| L3 | `ARCHITECTURE.md` §4 契约第 4 条 | 不变式与责任边界写入宪法级文档，`app_ymodem_demo.c` 的点状规避随之删除 |

## 2. 关键认知修正：不变式不是"缓冲 4 字节对齐"

第一次实现按"buf 非 4 对齐才中转"，实测**立刻把 WAV 播放打挂**：

```
E/BSP_AUDIO audio_fill_fail: Playback aborted: stereo read failed
                        status=-1  want=4096  got=434  remaining=175966
```

调用方缓冲 `s_audio_buf` 本身 4 字节对齐、文件位置是数据起始 78 字节（该 WAV 多一个 `LIST/INFO` 块，
176478 − 78 = 176400）。FatFS 的 direct 路径会**先把用户指针推进到扇区边界**（推进量 `512 − fptr%512 = 434`），
于是交给 `disk_read` 的地址是 `buf + 434`，天然 4n+2。因此真正的不变式是：

```
交给 DMA 存储后端的地址 ≡ buf − fptr (mod 4)   →   要求 buf ≡ fptr (mod 4)
```

（`ssz` 是 4 的倍数，故推进量 ≡ −fptr (mod 4)。）L2 的判定据此改写，并把 `sd_diskio` 的 L1 保留为兜底红线。

**推论**：凡"文件位置不是 4 的倍数"的读（如非 44/78 对齐头之后）都在旧路径上静默位移过——播放能出声但内容错位，
属于此前未被发现的一层。L1 生效后它变成显式失败，这是目的而非副作用。

## 3. 新的未决缺陷：背靠背单扇区 DMA 写会错开 2 字节（非对齐问题）

把 L2 暂存区取 512（即每次一笔单扇区写）时，**Ymodem→SD 变成确定性错误**（三次读同为 `088D2238`，非间歇）：

```
偏移 512..531 与 PC 一致；自 532 起整体错开 2 字节   ← 第二笔单扇区写的开头丢 2 字节
```

即：**传输形状决定后果**。一笔多扇区写（1024=2 扇区）今天两次验证逐字节正确；
拆成两笔连续单扇区写则确定性错 2 字节。L2 遂改为段体**批量整扇区下发**（暂存区 1KB），恢复已知良好形状。

同族的间歇症状是历史签名 **`mismatches=36 bad@8..43`**（本轮 `fatfs_test align` 的 raw 轮次仍复现，3 次跑中 2 次出现；
后续两轮 0 复现）。它发生在**指针完全合法**的 raw `f_write` 上，L1/L2 都覆盖不到，方向指向 SDIO 数据路径的
传输边界处理（`WriteStatus` 由 DMA/数据结束中断置位 vs 卡实际编程完成、FIFO 复位），而非总线信号质量。
已登记 `ARCHITECTURE.md` §9，作为独立待办，不与本次收口混淆。

**被实测否证的假设（记录以免重走）**：栈溢出。`startup_stm32f407xx.s` 中 `Stack_Size EQU 0x2000`（8 KB），
探针栈上仅约 600 B，形状也对不上 → 排除。电气/上拉/SW7 拨码亦已在上一批次排除。

## 4. 顺带修掉的真实缺陷：`bsp_audio` 填充期吞错导致总线永久占用

原代码把读失败静默成 `got = 0`，于是 `s_data_remaining` 永不归零 → 填充定时器无限自续期 →
**一次坏读就把 SPI2/I2S2 占用权永久占住**（实测：卡死后所有 flash 访问报 `-5 BSP_BUSY`，播放器只静音不报错），
且第二次 `play_wav` 直接 `BSP_BUSY` 无输出。改为：失败必 `log_e` 一次并置标志，定时器/预填路径负责停播与释放总线。

另修一处同类静默：EOF 判据必须与**未截断**的半区容量比较（`got < want`），若与 `s_data_remaining`
截断后的 `asked` 比较，末轮恰好耗尽剩余量时永远判不出结束——这是我改此函数时自己引入又当场抓出的。

## 5. SPI 侧规则与 SD 侧不同（照搬会误伤）

`Core/Src/spi.c`：`hspi1/hspi2.Init.DataSize = SPI_DATASIZE_8BIT`。DMA 控制器可按字节搬运，
故 SPI **不存在** SDIO IDMA 那种"丢地址低 2 位"的隐患；给 `port_spi_*_dma` 加 4 字节对齐拒绝会误伤合法调用。
真实约束是两条，已按数据宽度动态判定：

- `Init.DataSize` 为 16 位时需 2 字节对齐（8 位时无对齐要求）；
- 缓冲必须落在主 SRAM（`0x20000000..0x20040000`）；**CCM 对 DMA 完全不可达**——这一条在把 40 KB 空闲
  CCM 规划为静态池用途时（下一步）是关键护栏。

## 8. 同批次收口：错误语义透传与验收口

上一批次把“被占用”做成了快速失败，但原因码在 VFS 被一纵压成 `BSP_ERROR`，上层分不清
“稍后重试”与“真失败”。本批次补上：

| 新增 | 作用 |
|---|---|
| `s_ff_err_to_bsp()` / `s_lfs_err_to_bsp()` | 把 `FR_*` / `LFS_ERR_*` 映射到可区分状态码，不再一律 `BSP_ERROR`；原先全部调用点改为走映射 |
| `bsp_lfs_get_last_error()` 门闩 | 本仓 LittleFS v2.11 无 `LFS_ERR_BUSY`，块设备被总线拒绝只能报 `LFS_ERR_IO`；VFS 据此还原为 `BSP_BUSY`（可重试语义） |
| `fatfs_test rm <path>` | `bsp_file_remove` 自上一批以来只有 Ymodem 内部在用、无验收入口；现补上，并顺便清掉误传的 `0:/cut.wav` |
| `fatfs_test crc` 输出带 status | 否则新语义在板上不可观察，等于没做 |

实测：

```
audio_bus_switch i2s → crc flash/Tour_France.wav → crc: open ... failed (status=-5)   ← BSP_BUSY，可重试
audio_bus_switch spi → crc flash/Tour_France.wav → crc32=7A6FD6F4 short=0        ← 切回即恢复
rm 0:/cut.wav → Removed ；再 rm → failed (status=-7)                            ← BSP_ENODEV，区分生效
dump 0:/cut.wav → open failed                                                    ← 确认真删
align → U1/U2 仍被拒（rejects=+2）、V1/V2 仍正确（staged=+3）；唯一 FAIL 是 A 组 raw 的 36 字节岛（第 3 节未决项）
编译 0 Error；Code=335284 / RO=27512 / RW=544 / ZI=154888（与上批持平）
```

## 9. 同批次续做：LittleFS 专用静态池与重入守卫

针对 §7 第 4 项。先量准分配面再动手，结论比预想小得多：本仓 LittleFS v2.11 全库**只有一处**调用分配器
（`lfs.c:3193` 打开文件时的 `file->cache.buffer`，大小 = `cache_size` = 256 B）；挂载期的
rcache/pcache/lookahead 已由 `bsp_lfs.c` 静态提供，不经过分配器。所以不需要 `LFS_NO_MALLOC`——
而且**绝对不能用它**：v2.11 在该宏下直接不编译 `lfs_file_open()`，会迫使 `lv_port_fs.c` 等全部改用
`lfs_file_opencfg()` 并自备缓冲，侵入第三方胶层。

改用 LittleFS 官方指定的可替换点（`lfs_util.h` 的 `LFS_DEFINES` 头文件注入）：

| 新增 | 作用 |
|---|---|
| `BSP/Board/lfs_defines.h` | 仅定义 `LFS_MALLOC/LFS_FREE` 指向专用池；**一行未改 lfs.c / lfs_util.c**，上游升级无痛 |
| `BSP/Board/bsp_lfs_pool.c/.h` | 6 槽 × 256 B 定长池；尺寸不匹配不切分而是计数失败；只认自己发出的地址（重复/外来释放不破坏池）；输出 peak / alloc_fail 水位 |
| `lfs_pool` 命令 | 水位上看板——否则无法区分“真的走了池”与“碰巧 peak=0” |
| `LFS_THREADSAFE` + `lfs_lock_cb/lfs_unlock_cb` | 只置一个标志位、**不关中断**；嵌套进入时置总线门闩为 `BSP_BUSY` 并报错，把“静默互踩缓存”变成显式失败 |

两处设计上的相互呼应：

1. 池经 `.sct` 点名放入 CCM（与 LVGL 堆同区域）。**前提是可行**：flash 读写全程轮询 SPI 不经 DMA；
   而本轮 `port_spi` 新增的 DMA 可达性校验正是这条前提的护栏——将来有人把 W25Q 改成 DMA，
   会当场 `BSP_EINVAL`，而不是静默搬回垃圾。顺手把一直空着的 40 KB CCM 开始用起来。
2. 重入守卫失败时复用 A 的 `bsp_lfs_get_last_error()` 门闩，因此它向上仍呈现为可重试的 `BSP_BUSY`，
   与总线占用同一语义（不新增错误码）。

实测（当前固件）：

```
开机后          lfs pool: 6 slots x 256 B, peak=1, alloc_fail=0     ← 证明分配真的走了池
连开 9 次文件   全成功，peak=1、alloc_fail=0                        ← 无槽位泄漏（有泄漏则第 7 次必失败）
audio_bus_switch i2s → crc flash/…  status=-5；切回 spi → crc=7A6FD6F4 ← 失败路径不卡锁
lvgl_fs_test   写 55 字节读回一致；lfs_diag  A=0 fails B=0 fails
fatfs_test align  9/9 PASS，rejects=+2、staged=+3（契约未因锁/池改动而退化）
Ymodem→flash   SUCCESS，板端 CRC32 = PC 基准 7A6FD6F4
play_wav       Playing → Playback finished（980ms）
```
