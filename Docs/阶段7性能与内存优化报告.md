# 阶段七性能与内存优化报告

在天空星筑基板（基于 STM32F407VET6 芯片，512 KB Flash，128 KB 主 SRAM + 64 KB CCM RAM）的硬件架构下，针对当前 LVGL 界面刷新瓶颈以及后续集成以太网（LwIP）和音频（I2S）的资源分配问题，我们进行了深入的性能审计与内存架构重构。以下是本阶段的详细优化报告。

---

## 一、 性能瓶颈与设计考量

### 1. I/O 吞吐与硬件极限（SPI2 限制）
*   **物理瓶颈**：板载的外部闪存 W25Q128 挂载在 **SPI2** 总线上。在 STM32F407 的时钟树中，**SPI2** 属于 **APB1** 低速总线域（最大时钟频率 42 MHz）。在最小的二分频下，**SPI2** 的极限物理传输速率只能达到 **21 MHz**。
*   **总线带宽**：由于芯片没有硬件 Quad-SPI 控制器，只能工作在 1-bit 标准 SPI 模式，导致从外部 Flash 读取数据时物理吞吐量存在硬天花板。
*   **结论**：**SPI2** 速率限制在 **21 MHz** 属于硬件总线的固有属性，无法通过软件配置进一步提升。

### 2. 外部 Flash 读写采用阻塞轮询的合理性
在嵌入式文件系统（如 LittleFS / FatFS）中，针对 Flash 的数据读取必须使用**同步阻塞轮询**模式，使用非阻塞 DMA 在此场景下不合适，主要基于以下工程考量：
*   **同步设计本质**：文件系统层（如 **lfs_file_read**）是纯同步阻塞式 API。如果在驱动底层启动非阻塞 DMA，文件系统层由于无法立刻拿到数据，必须在回调中编写 **while(dma_busy);** 循环死等，使得非阻塞传输退化回阻塞等待，无法节省 CPU。
*   **DMA 启动开销**：文件系统读取多为频繁的元数据与索引小包（通常为几字节至几十字节）。启动 DMA 涉及配置源/目的地址、传输长度及清除中断标志，这些软件开销在传输小数据包时，其耗时甚至超过了直接用 CPU 轮询读取的耗时。
*   **RTOS 的局限**：即便在 RTOS 环境下通过 DMA 中断唤醒挂起线程，由于 LVGL 渲染也是同步等待当前图片解码数据，它同样会被阻塞在当前渲染任务中，对于界面刷新率没有实际的提升。

### 3. 显示刷新卡顿的根本原因与黄金解决法则
*   **卡顿根源**：LVGL 通过 LittleFS 从外部 W25Q128 动态加载图片时，由于文件系统层层寻址及 21MHz SPI 总线的低速阻塞式读取，单张图片的加载延迟极高，导致屏幕刷新呈现出明显的扫描线和撕裂感。
*   **黄金法则（工程必行准则）**：
    *   **高频交互资产内置化**：所有核心 UI、图标、常用中文字体，**绝对禁止**放置在外部 Flash 中动态加载。必须使用 LVGL 官方工具将其转换为 C 语言数组，并使用 **const** 关键字修饰，直接编译到**片内 Flash** 中。以此避开文件系统和 SPI 总线，利用 168MHz 的 CPU 内部总线实现直接、瞬时读取。
    *   **外部 Flash 仅作非高频资产存储**：外部 Flash 仅用于存放背景图、长篇说明文本、非即时交互动画或通过 Ymodem 动态更新的非关键资产。

## 二、 内存与固件深度优化成果

为腾出空间容纳 LwIP（以太网）和 I2S（音频）的 DMA 缓冲区及协议栈，我们实施了针对性的内存优化方案：

### 1. 激活 CCM RAM，释放主 SRAM (ZI-Data)
*   **问题**：以太网 DMA 描述符、音频 I2S 乒乓缓冲区以及 LCD 显存缓冲区**物理上无法使用 CCM RAM**，因为 CCM RAM 不挂载在总线矩阵上，DMA 控制器对其寻址会直接导致 **HardFault**。因此，必须将主 SRAM 中非 DMA 变量清空，腾给 DMA 使用。
*   **解决动作**：
    1.  手动接管并修改 Keil 分散加载文件 **SkyStar_BSP_HAL.sct**，关闭 Keil 图形化布局接管（魔法棒中取消勾选 **Use Memory Layout from Target Dialog**）。
    2.  开辟独立的 **RW_IRAM_CCM** 运行域，通过链接器将 LVGL 核心静态物理堆 **lv_mem_core_builtin.o**（**24 KB**）整体强制定向到 0x10000000 起始的 CCM RAM 空间。
*   **量化收益**：主 SRAM1/2 物理空间瞬间释放 **24.00 KB**。主内存占用从 **89.5 KB** 大幅下降至 **65.5 KB**，空闲出的 **38.5 KB** 通用 SRAM 足够后续 LwIP 和 I2S 音频分配 DMA 描述符与环形队列。

### 2. 深度裁剪 LVGL 组件，压缩片内 Flash 占用
*   **问题**：LVGL 默认编译并链接了大量未使用的复杂组件（日历、键盘等）以及软件渲染器的各色彩变体，占用片内 Flash 极多。
*   **解决动作**：
    1.  在 **lv_conf.h** 中将 **LV_USE_CALENDAR**、**LV_USE_KEYBOARD**、**LV_USE_CHART** 等全部设为 **0**。
    2.  将默认主题 **LV_USE_THEME_DEFAULT** 改为 **0**，断开默认主题对小部件的链式库函数引用。
    3.  关闭软件渲染器中不需要的色彩变体，仅保留物理屏幕必需的 **RGB565** 与 **RGB565_SWAPPED**。
*   **量化收益**：
    *   固件体积由原本的 **397.1 KB** 大幅压低至当前的 **300.0 KB**，**净释放片内 Flash 空间达 97.1 KB**。
    *   编译过程中的无用组件冗余警告从 **1891 个** 缩减至 **96 个**，减少了 95% 的编译噪声。
    *   为以太网协议栈（LwIP，约 50KB）与音频解码库（约 30KB）集成提供了绝对安全的 ROM 物理余量。

### 3. 显示双缓冲区配置与硬件安全
*   **配置**：**lv_port_disp.c** 中分配了局部刷屏双缓冲区 **buf_2_1** 与 **buf_2_2**（大小为 `240 * 40 * 2` 字节，共占 37.5 KB 物理 SRAM）。
*   **DMA 兼容**：上述缓冲区在声明中**未**被修饰 **.ccmram** 段，默认保留在普通 **SRAM1** 中，从而与底层的 **SPI1 DMA 异步刷新机制** 完美兼容，绝不会引发 DMA 寻址硬限制导致的系统死机。

---

## 三、 结论

当前 **SkyStar V2** 平台的内存拓扑与优化工作已圆满完成。在保留全部 LVGL 核心框架的前提下，我们通过“**CCM RAM 变量隔离**”和“**无用组件死码消除**”，为系统后续集成高带宽以太网和 I2S 音频彻底铺平了道路，系统具备在裸机或 RTOS 下稳定运行该综合功能的底层基础。
