## 1. 核心理念

### 1.1 基本原则

| 原则 | 说明 |
|------|------|
| **KISS** | Keep It Simple, Stupid — 简洁至上，避免过度工程化 |
| **第一性原理** | 立足根本剖析问题，不盲从惯例 |
| **事实为本** | 以事实为最高准则，有误必纠 |
| **渐进式开发** | 多轮迭代，先调研再设计再编码 |

### 1.2 开发流程

```
需求分析 → 方案设计 → 评审确认 → 任务分解 → 编码实现 → 测试验证
```

## 2. 架构分层

### 2.1 三层架构

```
┌─────────────────────────────────────────────────┐
│                   Board 层                       │
│         (板级服务：bsp_lcd, bsp_key...)          │
├─────────────────────────────────────────────────┤
│                   Driver 层                      │
│         (设备驱动：dev_st7789, dev_w25q...)      │
├─────────────────────────────────────────────────┤
│                  Interface 层                    │
│         (硬件抽象：port_spi, port_i2c...)        │
└─────────────────────────────────────────────────┘
```

### 2.2 层级职责

| 层级 | 命名前缀 | 职责 | 依赖方向 |
|------|----------|------|----------|
| **Board** | `bsp_` | 板级业务封装，面向应用 | 依赖 Driver |
| **Driver** | `dev_` | 设备驱动实现，芯片级封装 | 依赖 Interface |
| **Interface** | `port_` | 硬件抽象层，屏蔽 MCU 差异 | 依赖 HAL/LL |

### 2.3 依赖规则

- **上层可依赖下层**，下层禁止依赖上层
- **同层模块禁止循环依赖**
- 跨层调用只能通过公开接口

## 3. 命名规范

### 3.1 文件命名

| 类型 | 格式 | 示例 |
|------|------|------|
| Board 层 | `bsp_<功能>.c/h` | `bsp_lcd.c`, `bsp_key.c` |
| Driver 层 | `dev_<芯片>.c/h` | `dev_st7789.c`, `dev_w25q.c` |
| Interface 层 | `port_<外设>.c/h` | `port_spi.c`, `port_i2c.c` |

### 3.2 函数命名

| 层级 | 格式 | 示例 |
|------|------|------|
| Board 层 | `bsp_<模块>_<动作>` | `bsp_lcd_init()`, `bsp_key_scan()` |
| Driver 层 | `<芯片>_<动作>` 或统一前缀 | `lcd_init()`, `w25q_read()` |
| Interface 层 | `port_<外设>_<动作>` | `port_spi_write()`, `port_i2c_read()` |
| 私有函数 | `static` + `s_` 前缀或模块前缀 | `static void st7789_write_cmd()` |

### 3.3 变量命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 局部变量 | `snake_case` | `uint16_t pixel_count;` |
| 全局变量 | `g_` 前缀 | `uint8_t g_system_state;` |
| 静态变量 | `s_` 前缀 | `static uint16_t s_lcd_width;` |
| 结构体成员 | `snake_case` | `.pin_id`, `.buffer_size` |
| 指针变量 | `p_` 前缀或 `*` 靠变量 | `uint8_t *p_data;` 或 `uint8_t *data;` |

### 3.4 宏与枚举命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 宏定义 | 全大写 + 下划线 | `#define LCD_WIDTH 240` |
| 带参数宏 | 全大写 + 括号包裹 | `#define MAX(a, b) ((a) > (b) ? (a) : (b))` |
| 枚举值 | 大写 + 模块前缀 | `PORT_SPI_1`, `BSP_OK`, `LCD_COLOR_RED` |
| 枚举类型 | `xxx_t` 后缀 | `typedef enum { ... } port_spi_id_t;` |

### 3.5 宏定义格式规范

#### 3.5.1 括号使用规则

| 场景 | 括号要求 | 原因 |
|------|----------|------|
| 函数式宏参数 | **必须** | 避免运算优先级问题 |
| 函数式宏整体 | **必须** | 避免上下文运算优先级问题 |
| 表达式宏 | **必须** | 同上 |
| 简单单值宏 | 推荐 | 统一风格，避免遗漏 |

```c
/* 正确：函数式宏参数和整体都加括号 */
#define MAX(a, b)         ((a) > (b) ? (a) : (b))
#define MIN(a, b)         ((a) < (b) ? (a) : (b))
#define ALIGN_UP(x, n)    (((x) + (n) - 1) & ~((n) - 1))
#define BIT_SET(reg, bit) ((reg) |= (1U << (bit)))
#define BIT_CLR(reg, bit) ((reg) &= ~(1U << (bit)))

/* 错误：缺少括号导致潜在问题 */
#define SQUARE(x)         (x * x)           // SQUARE(1+2) = 1+2*1+2 = 5，预期 9
#define DOUBLE(x)         x + x             // DOUBLE(1)*2 = 1+1*2 = 3，预期 4

/* 正确：表达式宏加括号 */
#define BUFFER_SIZE       (4096)
#define TIMEOUT_MS        (1000U)

/* 可接受：简单单值宏（但推荐统一加括号） */
#define CMD_NOP           0x00
#define CMD_RESET         0x01

/* 推荐：统一加括号 */
#define CMD_NOP           (0x00U)
#define CMD_RESET         (0x01U)
```

#### 3.5.2 U 后缀使用规则

**MISRA C:2012 Rule 7.2**：无符号整数常量应加 `U` 后缀。

| 场景 | U 后缀 | 原因 |
|------|--------|------|
| 位掩码 | **必须** | 避免符号扩展陷阱 |
| 寄存器值/命令 | **推荐** | 嵌入式常见陷阱 |
| 移位操作数 | **必须** | 避免移位溢出 |
| 普通计数/尺寸 | 可选 | 风险较低 |
| 枚举值 | 可选 | 类型已明确 |

```c
/* 必须加 U：位掩码 */
#define ST7789_MADCTL_MY       (0x80U)
#define ST7789_MADCTL_MX       (0x40U)
#define ST7789_MADCTL_BGR      (0x08U)
#define ENABLE_MASK            (0x01U)

/* 推荐加 U：寄存器命令 */
#define ST7789_CMD_NOP         (0x00U)
#define ST7789_CMD_SWRESET     (0x01U)
#define ST7789_CMD_SLPIN       (0x10U)

/* 必须加 U：移位操作 */
#define BIT(n)                 (1U << (n))
#define FLAG_ENABLE            (1U << 0)
#define FLAG_BUSY              (1U << 1)

/* 可选：普通常量 */
#define BUFFER_SIZE            (4096)
#define MAX_RETRY              (3)
#define LCD_WIDTH              240
#define LCD_HEIGHT             320

/* 危险示例：不加 U 导致的问题 */
int result = 0x80 << 24;      // 危险！0x80 是 int，左移可能溢出
int result = 0x80U << 24;     // 安全：0x80U 是 unsigned，无符号扩展

/* 枚举值：类型已明确，U 后缀可选 */
typedef enum
{
    STATE_IDLE = 0,
    STATE_RUNNING = 1,
    STATE_ERROR = 2
} state_t;
```

#### 3.5.3 推荐的统一风格

```c
/* 寄存器命令/位掩码：括号 + U 后缀 */
#define ST7789_CMD_NOP         (0x00U)
#define ST7789_CMD_SWRESET     (0x01U)
#define ST7789_MADCTL_MY       (0x80U)
#define ST7789_MADCTL_BGR      (0x08U)

/* 普通常量：括号可选，U 后缀可选 */
#define ST7789_BUFFER_SIZE     (4096)
#define ST7789_WIDTH           240
#define ST7789_HEIGHT          320
#define TIMEOUT_MS             (1000U)

/* 函数式宏：参数括号 + 整体括号 + U 后缀（如涉及位操作） */
#define MAX(a, b)              ((a) > (b) ? (a) : (b))
#define MIN(a, b)              ((a) < (b) ? (a) : (b))
#define BIT(n)                 (1U << (n))
#define ARRAY_SIZE(arr)        (sizeof(arr) / sizeof((arr)[0]))
```

#### 3.5.4 多语句宏

使用 `do { ... } while(0)` 包裹，确保宏可以像函数一样使用：

```c
/* 正确：多语句宏使用 do-while(0) */
#define SAFE_FREE(ptr) \
    do { \
        if ((ptr) != NULL) { \
            free(ptr); \
            (ptr) = NULL; \
        } \
    } while(0)

/* 使用时可以正常加分号 */
SAFE_FREE(buffer);  // 展开后语法正确

/* 错误：使用逗号或分号会导致问题 */
#define SAFE_FREE(ptr) free(ptr), ptr = NULL  // if 条件下行为异常
```

## 4. 代码格式

### 4.1 缩进与空格

| 项目 | 规则 |
|------|------|
| 缩进 | 4 空格，禁止 Tab |
| 大括号 | Allman 风格（独占一行） |
| 运算符两侧 | 加空格：`a = b + c` |
| 逗号后 | 加空格：`func(a, b, c)` |
| 分号后 | 加空格：`for (i = 0; i < 10; i++)` |

### 4.2 函数定义

```c
/* 正确：紧凑单行 */
bsp_status_t port_spi_write(port_spi_id_t bus, uint8_t *data, uint16_t len)
{
    /* 函数体 */
}

/* 错误：禁止人为换行对齐 */
bsp_status_t port_spi_write(port_spi_id_t bus,
                             uint8_t      *data,
                             uint16_t      len)
{
    /* 函数体 */
}
```

### 4.3 控制语句

```c
/* if 语句 */
if (condition)
{
    /* 分支 */
}
else
{
    /* 分支 */
}

/* for 循环 */
for (uint32_t i = 0; i < count; i++)
{
    /* 循环体 */
}

/* while 循环 */
while (is_busy)
{
    /* 循环体 */
}

/* switch 语句 */
switch (state)
{
    case STATE_IDLE:
        handle_idle();
        break;

    case STATE_RUNNING:
        handle_running();
        break;

    default:
        handle_error();
        break;
}
```

### 4.4 单行长度

- **最大 120 字符**
- 超长行在低优先级运算符处换行，运算符置于新行行首

```c
bsp_status_t ret = port_spi_tx_dma(bus,
                                   buffer,
                                   length,
                                   callback,
                                   user_data);
```

### 4.5 空行规则

| 位置 | 规则 |
|------|------|
| 函数之间 | 1 个空行 |
| 逻辑块之间 | 1 个空行 |
| 头文件包含块后 | 1 个空行 |
| 宏定义块后 | 1 个空行 |
| 结构体/枚举定义后 | 1 个空行 |

## 5. 注释规范

### 5.1 文件头注释

```c
/**
 * @file port_spi.c
 * @brief SPI 接口层实现
 * @note 封装 HAL SPI 接口，提供统一抽象
 */
```

### 5.2 函数注释（Doxygen 格式）

```c
/**
 * @brief 初始化 SPI 总线
 * @param bus SPI 总线 ID
 * @return bsp_status_t 执行结果
 *         - BSP_OK 成功
 *         - BSP_EINVAL 参数无效
 *
 * @note 调用前需确保 GPIO 已初始化
 *
 * @example
 *   bsp_status_t ret = port_spi_init(PORT_SPI_1);
 *   if (ret != BSP_OK) {
 *       // 错误处理
 *   }
 */
bsp_status_t port_spi_init(port_spi_id_t bus);
```

### 5.3 注释风格选择

| 场景 | 风格 | 示例 |
|------|------|------|
| 文件头、函数接口 | Doxygen `/** */` | 见上方示例 |
| 代码块说明 | 块注释 `/* */` | `/* 1. 初始化硬件 */` |
| 单行说明 | 行注释 `//` | `// 等待 DMA 完成` |
| 枚举值说明 | 行尾注释 `//` | `PORT_SPI_1,  // SPI1` |

### 5.4 注释语言

- **中文为主**：便于理解，言简意赅
- **英文为辅**：通用术语、寄存器名称

### 5.5 注释禁忌

- **禁止注释掉的代码**：删除而非注释
- **禁止冗余注释**：代码本身应清晰
- **禁止误导性注释**：注释需与代码同步更新

### 5.6 注释分隔符规范

**用途**：用于划分代码逻辑块，增强可读性。

**格式**：

```c
/* ================================================================
 * 分隔标题
 * ================================================================ */
```

**使用场景**：

| 场景 | 示例 |
|------|------|
| 枚举/宏分组 | 按功能分类的寄存器定义、命令码 |
| 函数分组 | 初始化函数、读写函数、回调函数 |
| 结构体成员分组 | 配置成员、状态成员、回调成员 |
| 代码逻辑块 | 初始化步骤、数据处理阶段 |

**示例**：

```c

 * ================================================================ */

    BSP_OK       =  0,
    BSP_ERROR    = -1,

 * ================================================================ */
```

```c

 * ================================================================ */

    [PORT_SPI_1] = &hspi1,
```

| 项目 | 要求 |

## 6. 头文件规范

### 6.1 头文件保护

```c
#ifndef __PORT_SPI_H
#define __PORT_SPI_H

#ifdef __cplusplus
extern "C" {
#endif

/* 内容 */

#ifdef __cplusplus
}
#endif

#endif /* __PORT_SPI_H */
```

### 6.2 包含顺序

```c
/* 1. 系统头文件 */
#include <stdint.h>
#include <stdbool.h>
#include <string.h>

/* 2. 项目公共头文件 */
#include "bsp_board.h"
#include "bsp_status.h"

/* 3. 模块内部头文件 */
#include "port_gpio.h"
```

### 6.3 头文件原则

| 原则 | 说明 |
|------|------|
| 自包含 | 头文件能独立编译 |
| 最小暴露 | 只暴露公开接口，隐藏实现细节 |
| 禁止定义变量 | 头文件只声明，不定义 |
| 禁止循环依赖 | A 依赖 B，则 B 不能依赖 A |

### 6.4 外部依赖包含规范

**原则**：每个源文件自行包含所需的外部库头文件，禁止集中包含在公共头文件中。

**外部库定义**：
- HAL 库（`stm32f4xx_hal.h`）
- CMSIS 库
- 第三方中间件（FreeRTOS、FatFS 等）

**规范说明**：

| 做法 | 是否允许 | 原因 |
|------|----------|------|
| 在 .c 文件中直接包含 HAL | ✅ 推荐 | 依赖清晰，编译隔离 |
| 在 bsp_board.h 中包含 HAL | ❌ 禁止 | 编译依赖膨胀，职责模糊 |
| 创建 bsp_hal_conf.h 集中管理 | ⚠️ 可选 | 适用于大型项目 |

**正确示例**：

```c
/* port_tick.c */
#include "port_tick.h"
#include "stm32f4xx_hal.h"  // 自己负责外部依赖

void port_tick_init(void)
{
    /* HAL 库已初始化 SysTick */
}

uint32_t port_tick_get_ms(void)
{
    return HAL_GetTick();
}
```

**错误示例**：

```c
/* bsp_board.h */
#include "stm32f4xx_hal.h"  // ❌ 禁止！所有包含 bsp_board.h 的文件都被迫依赖 HAL

/* port_tick.c */
#include "bsp_board.h"      // 间接获得 HAL，依赖不透明
```

**原因分析**：

1. **编译效率**：HAL 头文件修改时，只重编译直接依赖的文件
2. **职责清晰**：bsp_board.h 是 BSP 内部核心，不应绑定特定 HAL 库
3. **最小依赖**：每个文件只包含实际需要的头文件

## 7. 错误处理

### 7.1 状态码定义

```c
typedef enum
{
    BSP_OK       =  0,  // 成功
    BSP_ERROR    = -1,  // 通用错误
    BSP_EINVAL   = -2,  // 参数无效
    BSP_ENOMEM   = -3,  // 内存不足
    BSP_ETIMEOUT = -4,  // 超时
    BSP_BUSY     = -5,  // 资源忙
} bsp_status_t;
```

### 7.2 错误处理模式

```c
/* 模式 1：提前返回 */
bsp_status_t func(uint8_t *data, uint16_t len)
{
    if (data == NULL) return BSP_EINVAL;
    if (len == 0) return BSP_EINVAL;

    /* 正常逻辑 */
    return BSP_OK;
}

/* 模式 2：错误传递 */
bsp_status_t outer_func(void)
{
    bsp_status_t ret = inner_func();
    if (ret != BSP_OK)
    {
        return ret;  // 向上传递错误
    }

    return BSP_OK;
}
```

### 7.3 参数检查

```c
bsp_status_t port_i2c_read(port_i2c_id_t bus, uint8_t addr, uint8_t *data, uint16_t len)
{
    /* 1. 边界检查 */
    if (bus >= PORT_I2C_MAX) return BSP_EINVAL;

    /* 2. 空指针检查 */
    if (data == NULL) return BSP_EINVAL;

    /* 3. 逻辑检查 */
    if (len == 0) return BSP_EINVAL;

    /* 正常逻辑 */
    return BSP_OK;
}
```

## 8. 安全规范

### 8.1 内存安全

| 规则 | 说明 |
|------|------|
| 禁止数组越界 | 访问前检查索引范围 |
| 禁止内存泄漏 | 动态分配需对应释放 |
| 禁止野指针 | 释放后置 NULL |
| 禁止未初始化使用 | 变量声明时初始化 |

### 8.2 并发安全

| 规则 | 说明 |
|------|------|
| 全局变量保护 | 中断/多线程访问需加锁或 volatile |
| 避免优先级反转 | 合理设置中断优先级 |
| 避免死锁 | 按固定顺序获取锁 |

### 8.3 硬件安全

| 规则 | 说明 |
|------|------|
| 超时保护 | 所有阻塞操作需有超时机制 |
| 错误恢复 | 外设错误需有恢复策略 |
| 硬件验证 | 调试时优先排查硬件问题 |

## 9. 日志与输出规范

### 9.1 printf 与 log_x 的核心差异

在配备非阻塞收发机制后，`printf` 和 `log_i` 虽都不阻塞 CPU，但核心设计哲学截然不同。

| 维度 | `printf` | `log_x` (EasyLogger) |
|------|----------|----------------------|
| **信息结构** | **裸数据输出**：无上下文，需手动硬编码位置信息 | **结构化上下文**：自动注入时间戳、级别、标签、函数名、行号（即“黑匣子”轨迹） |
| **过滤控制** | **全有或全无**：依赖 `#ifdef` 静态预编译控制 | **动态过滤**：支持运行时按级别、标签、关键字在线动态裁剪输出粒度 |
| **并发安全** | **潜在交织**：无锁保护，多任务/中断抢占时输出易粘连、混乱 | **原子安全**：内置上锁/解锁机制，多任务并发下保证单条日志完整独立 |
| **视觉检索** | **纯文本流**：无级别区分，手动编写 ANSI 颜色码极其混乱 | **视觉分级**：天然绑定颜色（如 ERROR 红底），海量日志下可凭本能快速锁定异常 |
| **后端扩展** | **单一介质**：强绑定控制台标准输出流（通常仅串口） | **多维存储**：支持前端解耦，插件式同步转存至 SPI Flash、FatFS 或网络远端 |

### 9.2 输出流使用界限

**规范 1：驱动层与系统后台（绝对禁区）**
- **禁令**：**严禁**在底层的 `port_` 层、`dev_` 层驱动及后台状态机、轮询任务中使用 `printf`。
- **要求**：必须根据严重程度使用 `log_d`, `log_i`, `log_w`, `log_e` 记录底层硬件初始化状态、总线超时或运行错误。

**规范 2：CLI / 人机交互（纯净排版）**
- **禁令**：在打印纯文本菜单、开机 ASCII 图形 Logo、或者要求对齐的数据表格时，**禁止**使用 `log_x`。
- **要求**：此类追求视觉排版的纯文本输出，**必须**使用 `printf`（或 Letter Shell 原生的 `shellPrint`），以避免日志前缀元数据破坏视觉排版。

**规范 3：Shell 调试指令（混合应用）**
- **状态反馈**：若是展示单次操作结果（如“设备已开启”），推荐使用 `log_i`，既给出明确提示又在系统时间轴上留存了操作痕迹。
- **用法提示**：若是响应 `help` 罗列复杂的命令格式提示，使用 `printf` 或 `log_e` 均可，但当提示包含过多对齐格式时，退回使用 `printf` 更为合理。

```c
/**
 * @file port_spi.h
 * @brief SPI 接口层头文件
 * @note 提供统一的 SPI 操作接口
 */

#ifndef __PORT_SPI_H
#define __PORT_SPI_H

#include <stdint.h>
#include "bsp_board.h"

/* SPI 总线 ID 枚举 */
typedef enum
{
    PORT_SPI_1 = 0,  // SPI1
    PORT_SPI_2,      // SPI2
    PORT_SPI_MAX     // 计数哨兵
} port_spi_id_t;

/* DMA 回调函数类型 */
typedef void (*port_spi_dma_cb_t)(bool success, void *user_data);

/* 公开 API */
bsp_status_t port_spi_init(port_spi_id_t bus);
bsp_status_t port_spi_write(port_spi_id_t bus, uint8_t *data, uint16_t len);
bsp_status_t port_spi_tx_dma(port_spi_id_t bus, uint8_t *data, uint16_t len,
                             port_spi_dma_cb_t cb, void *user_data);
bool port_spi_is_dma_busy(port_spi_id_t bus);

#endif /* __PORT_SPI_H */
```

```c
/**
 * @file port_spi.c
 * @brief SPI 接口层实现
 */

#include "port_spi.h"
#include "spi.h"

/* 硬件句柄映射 */
static SPI_HandleTypeDef *s_spi_map[] = {
    [PORT_SPI_1] = &hspi1,
    [PORT_SPI_2] = &hspi2,
};

/**
 * @brief 初始化 SPI 总线
 */
bsp_status_t port_spi_init(port_spi_id_t bus)
{
    if (bus >= PORT_SPI_MAX) return BSP_EINVAL;

    SPI_HandleTypeDef *hspi = s_spi_map[bus];
    if (hspi == NULL) return BSP_ERROR;

    /* HAL 初始化由 CubeMX 完成，此处仅验证状态 */
    if (hspi->State == HAL_SPI_STATE_RESET) return BSP_ERROR;

    return BSP_OK;
}

/**
 * @brief 阻塞写入数据
 */
bsp_status_t port_spi_write(port_spi_id_t bus, uint8_t *data, uint16_t len)
{
    if (bus >= PORT_SPI_MAX) return BSP_EINVAL;
    if (data == NULL || len == 0) return BSP_EINVAL;

    SPI_HandleTypeDef *hspi = s_spi_map[bus];
    if (hspi == NULL) return BSP_ERROR;

    HAL_StatusTypeDef ret = HAL_SPI_Transmit(hspi, data, len, 1000);

    return (ret == HAL_OK) ? BSP_OK : BSP_ERROR;
}
```
