# SkyStar BSP V2 · 状态机设计与调试规范

虽然状态机的业务逻辑各异，但为了应对复杂的非阻塞并发需求，本框架彻底摒弃了传统 `while(1)` 中的阻塞轮询，转而采用基于 **MultiTimer** 的全回调（Callback-Driven）架构。本规范旨在标准化这种“伪事件驱动”模型下的开发顺序与防坑原则。

---

## 一、 核心架构：全回调与单向数据流

在本框架中，状态机的核心被彻底拆散，通过时间片轮询和事件委托进行异步协同。

1. **事件输入层（按键回调）**
   - **职责**：监听外界变化。
   - **动作**：通过按键底层触发的独立回调（如 **key2_short_cb**），仅调用事件投递接口，严禁直接执行业务。
2. **核心路由层（FSM 轮询回调）**
   - **职责**：作为系统大脑，消费事件并决定下一状态。
   - **动作**：由高频定时器（如 10ms 的 **fsm_timer_cb**）周期性唤醒，从全局变量中取事件，执行 **switch_state** 跳转。
3. **输出表现层（表现刷新回调）**
   - **职责**：驱动物理外设。
   - **动作**：各外设拥有自己独立频率的定时器回调（如 20ms 的 **rgb_timer_cb**、50ms 的 **heartbeat_timer_cb**），它们像无情的播放器，只根据当前的全局状态渲染物理现象，不关心状态是怎么来的。

> **架构收益**：完全消除了状态流转和物理控制的耦合。长按按键不会卡住跑马灯的刷新，状态的切换也不会干扰蜂鸣器的发声。

## 二、 编码与渐进调试顺序（实操标准）

切忌把所有代码写完再上电调试，必须遵循“从数据管道到外设端点”的自内向外构建法。

### 阶段 1：铺设事件管道与状态响应
- **编码动作**：
  1. 定义状态和事件枚举（如 **SYS_STATE_IDLE**，**SYS_EVENT_NEXT**）。
  2. 实现事件投递函数 **app_sys_monitor_post_event**（带边界判定）。
  3. 实现纯逻辑的状态切换动作 **switch_state**。
- **目的**：建立系统流转的数据大动脉，此时不涉及任何外部触发和定时器。

### 阶段 2：构建核心路由回调（大脑验证）
- **编码动作**：
  1. 编写核心路由回调 **fsm_timer_cb**，实现 `获取事件 -> 执行动作 -> 状态跳转` 的核心骨架，**并在末尾强制续期**。
  2. 初始化并启动 **timer_fsm**。
  3. 在 **Shell** 中导出强行注入状态的命令（如 **sys_set_state**）。
- **联调验证**：
  打开串口，不操作任何硬件，单纯敲击 Shell 命令。观察控制台 **log_i** 打印的跳转日志。验证纯软件核心引擎存活且逻辑正确。

### 阶段 3：编写输出表现回调（挂载执行器）
- **编码动作**：
  1. 分别编写诸如 **rgb_timer_cb** 或 **heartbeat_timer_cb**。
  2. 在回调内读取全局状态，执行各自的硬件操作。
- **联调验证**：
  依然使用 Shell 命令模拟状态切换。观察硬件外设（心跳灯、RGB、蜂鸣器）是否随虚拟命令同步变化。
  *排错注意：加入外设后若死机，100% 意味着刚加入的那个外设驱动有底层中断或时序问题（如 DMA 抢占）。*

### 阶段 4：对接输入源回调（闭环打通）
- **编码动作**：
  1. 在底层硬件输入（如按键库的 **key2_short_cb**）中，填入阶段 1 写好的投递动作 **app_sys_monitor_post_event**。
- **联调验证**：
  脱离串口命令，真实操作物理输入。由于骨架和输出均已在前面阶段验证完毕，此时如果系统异常，只可能是由于按键抖动、物理连线、或者事件产生频率过快导致的事件队列覆盖问题。

## 三、 防御性编程“五大铁律”

在使用本全回调架构时，必须强制遵守以下防错约定：

1. **单次定时器的无条件续期（最易踩坑）**
   在使用 **MultiTimer** 时，定时器属于单次触发（One-shot）。**必须在回调函数的最末尾无条件调用 `multiTimerStart` 续期**。如果因为当前没事件而在 if 内直接 return，定时器将永久死亡，系统陷入静默瘫痪。

2. **事件源越界拦截**
   在所有的事件投递入口，必须进行越界判定（如 `if (event >= SYS_EVENT_MAX) return;`），防止脏数据或游离指针写入导致未知事件分支执行。

3. **路由器的 Default 兜底分支**
   在编写状态路由判断的 `switch(state)` 或事件判断时，永远保留 `default:` 分支。通过 `log_w` 抛出警告，用来抓捕被遗漏处理的“迷失事件”或“非法状态”。

4. **禁止在表现层（输出回调）中反向修改状态**
   像 **rgb_timer_cb** 这种控制灯光的回调，对其而言系统状态变量应当被视为**只读**。绝对禁止在表现层回调中通过运算反推并修改主状态，否则将导致系统逻辑陷入严重混乱。

5. **自身跳转屏蔽**
   编写状态切换函数 `switch_state` 时，首句必须拦截自身向自身的跳转（如 `if (g_current_state == new_state) return;`），防止引发不必要的日志刷屏或外设重新初始化浪涌。
