# SkyStar BSP V2 - SDIO 写入接缝缺陷 排查移交报告 (SDIO Silent Write Corruption Handover)

> 状态：**未定位，已规避，可长期挂起**
> 日期：2026-09-24　分支/提交：`zcode_bsp` @ `c70147d`
> 一句话：TF 卡写入在**特定传输形状**下会静默丢/移字节——**不报错、CRC 也过**，只有逐字节比对能发现。

## 1. 影响与紧急度 (Impact & Urgency)

| 维度 | 结论 |
|---|---|
| 当前业务是否已出错 | **没有**。走 `bsp_file` 的路径全部实测干净：Ymodem→SD、Ymodem→flash 整文件 CRC = PC 基准；`crcmap` 44 块双遍零差异；`play_wav` 正常 |
| 什么会踩 | **绕过 VFS 的直写**（直接调 `f_write`）、**连续小笔写**（一笔 ≤1 扇区）、未来任何"分包落盘"功能（日志轮转、OTA 分片、FTP/HTTP 上传） |
| 最坏后果 | 静默损坏：文件存在、大小正确、`f_write/f_close` 全成功 → 若落盘物是固件/资源包且上层无校验，等同变砖 |
| 建议优先级 | **中**。不阻塞开发；一旦要新增"小块频繁写 SD"的功能，必须先处理 |

## 2. 两种症状 (Two Symptoms)

| # | 症状 | 实测数据 | 形状条件 | 复现率 |
|---|---|---|---|---|
| S1 | 文件头之后出现一段**固定长度**垃圾，前后均正确 | `mismatches=36`，位置恒为**偏移 8..43**（`bad@8,9,...,23...`），跨轮次长度与起点一致 | `disk_write(count=1)`，即一笔**单扇区**写（`A1 align 512x1`、`A4 align 2048x1`） | **间歇**：连续 3 次跑中 2 次出现，另 2 次为 0 |
| S2 | 从第二笔的开头起**整体平移 2 字节**，直到文件尾 | 偏移 512..531 与 PC 一致，**自 532 起错开 2 字节**；板端整文件 `crc32=088D2238`（应为 `7A6FD6F4`），三次读取同一错值 | 把 1024 字节**拆成连续两笔**单扇区写（曾把 L2 暂存区设成 512B 时触发） | **100% 必现** |

S2 是最有价值的一条：**同样的数据、同样对齐的缓冲，只改"拆成两笔"这一件事，损坏就从偶发变成必然** ⇒ 问题在"两次传输的接缝"，不在数据本身。

## 3. 为什么会静默 (Why It Is Silent)

SD 写链路上有三层"完成"，本仓代码只等到其中两层：

| 层 | 含义 | 谁来回答 | 现状 |
|---|---|---|---|
| ① 交付 | SDIO 自带 IDMA 把字节搬进外设 FIFO | `WriteStatus`（`HAL_SD_TxCpltCallback` → `BSP_SD_WriteCpltCallback`） | 已等待 |
| ② 排空 | 外设把 FIFO **最后一个字节**真正上线 | **只有 SDIO 自己的状态知道** | **无人确认**（与 ① 常被同一次中断视为同时完成） |
| ③ 落盘 | 卡内部编程完成、回到空闲态 | 卡对 CMD13 的答复（`BSP_SD_GetCardState()`） | 已等待（`SD_CheckStatusWithTimeout`，`SD_TIMEOUT = 30000`） |

CMD13 问的是**卡**，不是 MCU 的 FIFO。两笔写之间若 ② 未完成，第二笔的字节流就会与上一笔的尾巴重叠 ⇒ 丢/移若干字节。

**CRC 为什么救不了**：SD 写命令的 CRC16 由外设对"它实际发出的字节"生成、由卡对"它实际收到的字节"校验。丢在 FIFO 里的字节**从未上线**，于是两侧看到的是同一串"残缺但自洽"的数据 ⇒ CRC 通过、返回码全 `OK`。

## 4. 已排除项 (Ruled Out — 勿重走)

| 假设 | 判据（都实测过） | 结论 |
|---|---|---|
| DMA 缓冲未 4 字节对齐（SDIO IDMA 丢地址低 2 位） | 出错轮次 `src=0x20017A30 mod4=0` 且文件位置在扇区边界；且现在 L1 会把任何非对齐请求直接 `RES_PARERR`，不可能溜过 | 排除（但这条**是另一个已修的真缺陷**，见第 9 节） |
| 卡还在编程就被发起下一笔 | 每次 `SD_read/SD_write` 入口都 `SD_CheckStatusWithTimeout()` 等 CMD13 说空闲 | 排除 |
| 信号/时钟边沿余量、上拉、SW7 拨码 | SDMMC `ClockDiv=8` ⇒ 约 **2.7 MHz**（规范低速允许 25 MHz）；SW7 已全拨 SPI2 侧且软件优先级更高；**随机噪声给不出"固定长度 + 固定位置"的岛** | 基本排除（降速对照仍未做，见第 8 节 E1） |
| 栈溢出 | `startup_stm32f407xx.s` 中 `Stack_Size EQU 0x2000`（8 KB），探针仅用约 600 B | 排除 |
| 读卡回读假象 | 卡插 PC 读卡器实测，**卡中内容确实与源文件不同** | 排除（是真空损坏） |
| 未定义行为/对齐中转到丢数据 | L2 暂存区改回 1KB 批量整扇区后症状消失 | 与形状强相关，进一步支持"接缝"结论 |

## 5. 误判史 (Misjudgements — 供下一位校准)

1. "port_uart RX 溢出丢字节" ⇒ 否证：Ymodem 对整 1024 字节载荷算 CRC16，丢字节必致失配重传。
2. "LittleFS/W25Q 写路径坏 2/43 块" ⇒ 否证：那是**被 CAN(0x18) 中止的传输留下的残留坏文件**，其数据块已被复用给其它文件。
3. "flash 读非幂等" ⇒ 部分是我 `crcmap` 读窗 `static uint8_t win[64]`（仅 1 字节对齐）造成的**测量工具假象**；但随后"所以纯属对齐假象"的修正**又错了**（SPI 路径为轮询、不经 DMA）。
4. "36 字节岛是测量假象，已被对齐解释统一收编" ⇒ **今日否证**：它在指针完全合法的 raw 路径上仍复现。
5. "仲裁 release 不切回物理侧 → 控制线浮空 → 读随机错" ⇒ 否证：`io_read 0 2` 实测开关在 SPI2 侧。

教训：**同一观测可由多因解释**。凡"数据不一致"，必须先把 ①读失败 ②短读/提前返回 ③内容不同 三者分开报告，再谈归因（`fatfs_test crc` 已按此改造，会分别打印 `short=N`、`<READ FAILED>`）。

## 6. 判据与取证工具 (Toolbox)

板端（letter-shell）：

| 命令 | 用途 |
|---|---|
| `fatfs_test mount` | 挂载（`align` 前必需） |
| `fatfs_test align` | **主判据**：9 轮双向矩阵，逐轮 `=> PASS/FAIL`，末行 `--- rejects=+N (L1)  staged=+M (L2)  failures=K ---` |
| `fatfs_test crc <path>` | 整文件 CRC32 + `short=N` + 读失败标记 |
| `fatfs_test crcmap <path> 4096` | 分块 CRC 地图，**同命令内读两遍自比**（分离"读不稳"与"内容真坏"） |
| `fatfs_test dump <path> [off] [len]` | 字节级对照（看错位形状用） |
| `io_read 0 2` | PCA9555 上 SPI2/I2S2 模拟开关控制位电平 |
| `lfs_pool` / `flash_stable` / `lfs_diag` | 与 SDIO 无关，但可用来证明"SPI 侧无辜" |

PC 侧：

```bash

python -c "import binascii;d=open(r'<文件路径>','rb').read();print(len(d),'%08x'%binascii.crc32(d))"

# 发文件 / 负向（刻意少发）测试
```

## 7. 复现配方 (Repro)

```
1) 板上跑本仓库当前固件（zcode_bsp @ c70147d 或更新）
2) 冷启动（重新上电或重刷），不要接任何串口终端（COM3 独占）
3) 串口执行： fatfs_test mount
4) 串口执行： fatfs_test align        ← 连跑 3 次
   期望（说明缺陷在响）：A1/A4 之类"一笔单扇区"轮次出现 mismatches=36 bad@8,9,...
   期望（说明契约正常）：U1/U2 被拒 => PASS(rejected-by-L1)、V1/V2 干净 => PASS(byte-clean)
                        末行 rejects=+2、staged=+3
5) 量化复现率：把第 4 步重复 5 次，统计 A 组 mismatches>0 的轮次个数
```

判据不是"必现"而是"复现率 > 0" ⇒ **必须多跑几次**，单次通过不能作为"已修好"的证据。

## 8. 判决实验设计 (Experiments — 先确诊，别先改)

| # | 实验 | 判读 | 成本 |
|---|---|---|---|
| E1 | SDMMC 降一档（`Core/Src/sdio.c` 的 `ClockDiv 8 → 16`），跑第 7 步 5 遍 | 岛仍在 ⇒ 与时序余量无关，坐实"主机侧接缝"；岛消失 ⇒ 本文第 4 节的排除要收回，按信号完整性处理 | 1 次编译+烧录 |
| E2 | 在 `SD_write` 返回前，除 `WriteStatus` + CMD13 之外**再确认外设数据通路已空**（读 SDIO 状态/数据结束标志，必要时复位数据 FIFO 后再返回），跑 S2 形状（连续两笔单扇区） | 2 字节滑移消失 ⇒ 根因锁定在 ② 层，可出正式修复；仍在 ⇒ 转 E3/示波器 | 1 个文件改动，半天含回归 |
| E3 | 换一张 TF 卡 / 换一块板，重复第 7 步 | 复现率随卡变化 ⇒ 卡侧行为成分；一致 ⇒ 主机侧 | 需要备件 |
| E4 | 逻辑分析仪看 `PC12(SDIO_CK)/PD2(CMD)/PC8..11(D0..3)`，比对"应发字节"与"实发字节" | 直接看见哪几个字节没上线（这是唯一能给"证据级"结论的手段） | 需要仪器 |

推荐顺序：**E1 → E2**（都不需要额外硬件，且能互相排除）。

## 9. 现有兜底措施与其局限 (Existing Mitigations)

| 措施 | 位置 | 局限 |
|---|---|---|
| 写路径段体**批量整扇区、一次最多 1 KB**下发（减少接缝数量） | `BSP/Board/bsp_file.c` 的 `s_fatfs_write_staged()` 与 `BSP_FILE_ALIGN_STAGE_SIZE` | 只是把概率压低；**绕过 VFS 的 `f_write` 不受保护** |
| 非对齐/DMA 不可达缓冲在 disk 层**显式拒绝** `RES_PARERR` + 拒绝计数 | `FATFS/Target/sd_diskio.c`（`SD_DmaBufOk()`、`SD_GetBufRejectCount()`） | 治的是**另一条真缺陷**（SDIO IDMA 丢地址低 2 位 ⇒ 整块静默位移，Ymodem 载荷 `frame_buf+3` 必现），与本接缝无关 |
| VFS 统一对齐中转（判定不变式为 `buf ≡ 文件位置 (mod 4)`） | `BSP/Board/bsp_file.c` | 同上；另注意：FatFS 会把用户指针**推进到扇区边界**，故"缓冲对齐"并不足够 |
| 中止传输不再污染同名好文件（临时名 + 校验 + 改名提交） | `APP/demos/app_ymodem_demo.c` + `bsp_file_rename/remove` | 与本缺陷无关，但**极大降低"看到坏文件就怀疑写路径"的误导性** |

## 11. 接手前必须知道的项目约束 (Constraints)

1. **工具链**：Keil MDK ARMCC V5.06 update 5；编译 `python .agents/skills/build-keil/scripts/keil_builder.py --project MDK-ARM/SkyStar_BSP_HAL.uvprojx --target SkyStar_BSP_HAL`；烧录用 `flash-keil` 技能脚本。**烧录前确认没有 Keil GUI 占用 DAP-Link**（否则报 `Target DLL has been cancelled`，且可能半程擦除）。
2. **串口独占**：COM3 只能有一个持有者；用户的 Tabby/串口助手会让脚本 `PermissionError`。抓取脚本输出含 ANSI 转义，喂给解析器前要先剥。
3. **内存水位（改任何静态缓冲前必看）**：主 SRAM1 `.ANY` 仅剩 **112 B**（`RW_IRAM1 0x1BF90/0x1C000`）；C 堆仅 **4 KB**（`Heap_Size 0x1000`）；CCM 64 KB 中已用 26 KB（LVGL 池 + LittleFS 池），**还剩约 39 KB 空闲**。`CCM(0x10000000) 对所有 DMA 不可达` —— 这是本项目第二条硬约束。
4. **CubeMX**：外设配置以 `SkyStar_BSP_HAL.ioc` 为准，重新生成会覆盖 `Core/`；本项目在 `FATFS/Target/` 有手写薄层（`sd_diskio.c` 里的 `USER CODE` 区可安全放自定义代码）。
5. **`MDK-ARM/SkyStar_BSP_HAL.uvprojx` 不纳管**（`.gitignore` 第 7 节）：新增源文件/改宏/改包含路径需手工 `git add -f` 补交；且它不在版本树里 ⇒ **`git reset --hard` 或跨分支合并会删掉磁盘副本**（本项目已实际发生两次）。
6. **提交与分支**：中文 Conventional Commits；提交由用户发起；合入 `zcode_bsp` 用 `--no-ff`；不 push 受保护分支。
7. **既有已知问题清单**在 `Docs/01-map/ARCHITECTURE.md` 第 9 节（本缺陷为其中的"SDIO 传输边界缺陷"条目）。

## 14. 备注：为什么可以长期挂起

当前所有业务写入都走 VFS 的批量整扇区形状，实测干净；本缺陷只在"人为构造的小笔直写"里被钓出来（那是我们故意留的负向用例）。因此它的正确处置是：**保持 `fatfs_test align` 可跑、保持第 7 步判据可执行**，等出现"新增小块频繁写 SD"的需求时再按 E1→E2 确诊，避免在无需求时改动存储核心路径。
